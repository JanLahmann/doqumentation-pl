Konfiguracja QCSC-Prefect na klastrze Slurm

Ten przewodnik przygotowuje węzeł logowania klastra Slurm jako hosta przepływu pracy qcsc-prefect. Samouczek SQD dla qcsc-prefect zaczyna od wyniku tego przewodnika.

Po ukończeniu tego przewodnika będziesz mieć następujące elementy:

ElementGdzieZawartość
~/venv/qcsc-hostWęzeł logowania, host przepływu pracyPrefect, pakiety qcsc-prefect i polecenie qcsc-qrmi
~/venv/qcsc-nodeWęzły obliczeniowe, wewnątrz zadań SlurmWorker QRMI: QRMI z poleceniem task_runner oraz qcsc-prefect-qiskit
qrmi-runtimePrefectBlok, który nazywa Twoją instancję IBM Quantum® i QPU
qrmi_config.jsonWęzeł logowania i węzły obliczenioweTwój klucz API IBM Cloud®, instancje i Backendy dla QRMI

Każde polecenie uruchamiaj w terminalu na węźle logowania, chyba że krok mówi inaczej.

Wymagania wstępne​

  • Klaster Slurm z OpenMPI, PMIx i wtyczką QRMI SPANK, które instaluje administrator klastra. Poniższe przewodniki opisują te komponenty:

    • Quantum resource management interface (QRMI)

    • Wtyczka SPANK dla QRMI

    • Przewodnik użytkownika wtyczki SPANK

  • Katalog domowy i katalog roboczy, które węzeł logowania i węzły obliczeniowe widzą pod tymi samymi ścieżkami bezwzględnymi

  • Wychodzący dostęp HTTPS do GitHub, PyPI, IBM Quantum i Prefect Cloud z węzła logowania oraz do IBM Quantum z węzłów obliczeniowych

  • Konto IBM Quantum Platform z kluczem API IBM Cloud i co najmniej jedną instancją

  • Konto Prefect Cloud lub serwer Prefect, który sam hostujesz

  • Git, kompilatory C i C++, CMake, BLAS, LAPACK i MPI na klastrze, do kompilacji solverów z samouczka

uwaga

Przykłady używają partycji Slurm normal oraz węzłów obliczeniowych c1 i c2. Zastąp je nazwami z Twojego klastra.

Krok 1: Zaloguj się do węzła logowania​

# Run in a terminal on your computer.
ssh <user>@<login-node>

Krok 2: Zainstaluj uv​

Zainstaluj menedżera pakietów uv i sprawdź instalację:

curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"
uv --version

Krok 3: Ustaw ścieżki i utwórz katalog roboczy​

Ten przewodnik i samouczki używają dwóch zmiennych środowiskowych:

ZmiennaPrzykładPrzeznaczenie
QCSC_PREFECT$HOME/qcsc-prefectKopia robocza qcsc-prefect
QCSC_WORK_DIR/shared/work/qcsc-prefectKatalog roboczy zadań solvera i zadań QRMI

Obie ścieżki muszą leżeć w magazynie, który węzły obliczeniowe widzą pod tą samą ścieżką bezwzględną. Jeśli Twój klaster nie ma katalogu /shared, wybierz inną współdzieloną ścieżkę.

Ustaw zmienne i utwórz katalog roboczy. Ustaw zmienne ponownie w każdej nowej powłoce, zanim zaczniesz samouczek:

export QCSC_PREFECT="$HOME/qcsc-prefect"
export QCSC_WORK_DIR=/shared/work/qcsc-prefect
mkdir -p "$QCSC_WORK_DIR"

Aby ustawiać zmienne automatycznie w każdej nowej powłoce, dodaj je do ~/.bashrc:

# Optional
echo "export QCSC_PREFECT=$QCSC_PREFECT" >> ~/.bashrc
echo "export QCSC_WORK_DIR=$QCSC_WORK_DIR" >> ~/.bashrc

Krok 4: Sklonuj qcsc-prefect​

Sklonuj repozytorium i przełącz się na tag wydania, na przykład v0.3.1:

git clone https://github.com/qiskit-community/qcsc-prefect.git "$QCSC_PREFECT"
cd "$QCSC_PREFECT"
git checkout v0.3.1

Krok 5: Utwórz środowisko przepływu pracy​

Utwórz środowisko przepływu pracy z Pythonem 3.12 i aktywuj je:

uv venv ~/venv/qcsc-host -p 3.12
source ~/venv/qcsc-host/bin/activate

Zainstaluj pakiety qcsc-prefect. Opcja --no-deps zachowuje dokładne przypięte wersje między pakietami z checkoutu. Samouczek instaluje sam workflow:

cd "$QCSC_PREFECT"
uv pip install --no-deps \
  -e packages/qcsc-prefect-core -e packages/qcsc-prefect-adapters \
  -e packages/qcsc-prefect-blocks -e packages/qcsc-prefect-executor \
  -e 'packages/qcsc-prefect-qiskit[slurm]'

Sprawdź, czy polecenia są dostępne:

which prefect qcsc-qrmi

Aktywuj ~/venv/qcsc-host w każdej nowej powłoce na węźle logowania.

Krok 6: Zaloguj się do Prefect​

Zaloguj się do Prefect Cloud. Wybierz Paste an API key, wklej klucz API Prefect Cloud i wybierz swoją przestrzeń roboczą:

prefect cloud login

Sprawdź połączenie. Wynik pokazuje PREFECT_API_URL i Twoją przestrzeń roboczą:

prefect config view
Opcjonalnie: użyj własnego serwera Prefect

Pomiń tę uwagę, jeśli korzystasz z Prefect Cloud. Aby użyć własnego serwera Prefect zamiast Prefect Cloud, postępuj zgodnie z How to run and access a Prefect server on a Slurm login node, i ustaw adres swojego serwera w miejsce <server-host>:

# Optional: only for your own Prefect server
prefect config set PREFECT_API_URL=http://<server-host>:4200/api

Krok 7: Zapisz dane uwierzytelniające IBM Quantum​

Uruchom qcsc-qrmi login po zalogowaniu do Prefect, ponieważ zapisuje on blok qrmi-runtime:

qcsc-qrmi login

Odpowiedz na pytania:

  1. Wklej swój klucz API IBM Cloud. Klucz nie jest wyświetlany.

  2. Naciśnij Enter, aby użyć wszystkich instancji.

  3. Wpisz numer domyślnej instancji, w poniższym przykładzie 1.

  4. Wpisz numer lub nazwę domyślnego backendu, w poniższym przykładzie 4 (ibm_kingston).

Polecenie wypisuje też uwagę o węzłach obliczeniowych oraz wiersze [qrmi] dla sqd_blocks.toml, które przykład pomija (...). Wierszy [qrmi] nie potrzebujesz, ponieważ workflow odczytuje instancję i backend z bloku qrmi-runtime.

Polecenie qcsc-qrmi ma następujące podpolecenia:

PoleceniePrzeznaczenie
qcsc-qrmi loginZapisuje klucz API, instancje i backendy oraz zapisuje blok
qcsc-qrmi refreshPonownie wyszukuje instancje i backendy za pomocą zapisanego klucza
qcsc-qrmi listWypisuje instancje i backendy, bez klucza
qcsc-qrmi checkSprawdza, czy instancja z bloku może używać swojego backendu

Zainstaluj plik na węzłach obliczeniowych​

Wtyczka SPANK odczytuje qrmi_config.json na każdym węźle obliczeniowym, ze ścieżki podanej w plugstack.conf, często /etc/slurm/qrmi_config.json. Poproś administratora klastra o zainstalowanie Twojego ~/.qiskit/qrmi_config.json pod tą ścieżką. Zainstaluj go ponownie po każdym qcsc-qrmi login lub qcsc-qrmi refresh.

Pozostaw Session Mode bloku qrmi-runtime ustawiony na batch, ponieważ wtyczka SPANK zajmuje QPU w trybie batch.

Krok 8: Utwórz środowisko węzła obliczeniowego​

Worker QRMI działa na węźle obliczeniowym, we własnym środowisku. Utwórz je z tego samego checkoutu. Opcja --python utrzymuje aktywne ~/venv/qcsc-host:

cd "$QCSC_PREFECT"
uv venv ~/venv/qcsc-node -p 3.12
uv pip install --python ~/venv/qcsc-node/bin/python "qrmi[ibm]"
uv pip install --python ~/venv/qcsc-node/bin/python -e packages/qcsc-prefect-qiskit

Pakiet qrmi[ibm] udostępnia polecenie task_runner. Samouczek dodaje do tego środowiska hak kompilacji SQD i używa ~/venv/qcsc-node/bin/python jako python_executable w sqd_blocks.toml.

Sprawdź zapisane instancje i backendy. Polecenie nigdy nie wypisuje klucza:

qcsc-qrmi list
# Output
API key: set
premium-instance (premium, us-east) (default): ibm_boston, ibm_chicago, ibm_fez, ibm_kingston, ibm_marrakesh, ibm_phoenix, ibm_pittsburgh
open-instance (open, us-east): ibm_fez, ibm_kingston, ibm_marrakesh

Sprawdź, czy domyślna instancja może używać domyślnego backendu:

qcsc-qrmi check
# Output
premium-instance (premium, us-east) can use ibm_kingston.

Sprawdź, czy Slurm uruchamia zadanie na obu węzłach obliczeniowych, także z PMIx:

srun -N2 hostname
srun -N2 --mpi=pmix hostname
# Output of each command
c1
c2

Sprawdź środowisko węzła obliczeniowego i katalog roboczy na węźle obliczeniowym. Pierwsze polecenie nic nie wypisuje, gdy importy się powiodą:

srun -N1 ~/venv/qcsc-node/bin/python -c "import qrmi, qcsc_prefect.integrations.qiskit.qrmi.worker"
srun -N1 ls ~/venv/qcsc-node/bin/task_runner
srun -N1 ls -ld "$QCSC_WORK_DIR"

Kolejne kroki​

Zalecenia

  • Przeczytaj Size the SQD diagonalization for your HPC resources, aby wybrać węzły, rangi i wątki zadań solvera.

  • Przeczytaj QRMI sampler on Slurm, aby poznać worker QRMI i układ pliku qrmi_config.json.
