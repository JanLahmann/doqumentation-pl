Zacznij pracę z prymitywami

Nowy model wykonania — teraz w wersji beta

Dostępna jest teraz wersja beta nowego modelu wykonania. Kierowany model wykonania zapewnia większą elastyczność podczas dostosowywania przepływu pracy mitygacji błędów. Więcej informacji znajdziesz w przewodniku Kierowany model wykonania.

uwaga

Choć ta dokumentacja używa prymitywów z Qiskit Runtime, które umożliwiają korzystanie z backendów IBM®, prymitywy można uruchamiać u dowolnego dostawcy, korzystając zamiast tego z prymitywów backend. Dodatkowo możesz używać prymitywów referencyjnych do uruchamiania na lokalnym symulatorze wektora stanu. Szczegóły znajdziesz w artykule Dokładna symulacja z prymitywami Qiskit.

# Added by doQumentation — required packages for this notebook
!pip install -q numpy qiskit qiskit-ibm-runtime

Kroki opisane w tym temacie pokazują, jak skonfigurować prymitywy, poznać dostępne opcje konfiguracji oraz wywoływać je w programie.

Używanie Fractional Gates

Aby używać nowo obsługiwanych bramek ułamkowych (fractional gates), ustaw use_fractional_gates=True podczas pobierania backendu z instancji QiskitRuntimeService. Na przykład:

service = QiskitRuntimeService()
fractional_gate_backend = service.least_busy(use_fractional_gates=True)

Pamiętaj, że jest to funkcja eksperymentalna i może ulec zmianie w przyszłości.

Package versions

The code on this page was developed using the following requirements. We recommend using these versions or newer.

qiskit[all]~=2.3.0
qiskit-ibm-runtime~=0.43.1

Zacznij pracę z Estimator​

1. Zainicjalizuj konto​

Ponieważ Qiskit Runtime Estimator jest usługą zarządzaną, najpierw musisz zainicjalizować swoje konto. Następnie możesz wybrać QPU, którego chcesz użyć do obliczenia wartości oczekiwanej.

Postępuj zgodnie z krokami opisanymi w temacie Instalacja i konfiguracja, jeśli nie masz jeszcze skonfigurowanego konta.

from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()
backend = service.least_busy(
    operational=True, simulator=False, min_num_qubits=127
)

print(backend.name)
ibm_torino

2. Utwórz Circuit i obserwowalną​

Do prymitywu Estimator potrzebny jest co najmniej jeden Circuit i jedna obserwowalna jako dane wejściowe.

from qiskit.circuit.library import qaoa_ansatz
from qiskit.quantum_info import SparsePauliOp

entanglement = [tuple(edge) for edge in backend.coupling_map.get_edges()]
observable = SparsePauliOp.from_sparse_list(
    [("ZZ", [i, j], 0.5) for i, j in entanglement],
    num_qubits=backend.num_qubits,
)
circuit = qaoa_ansatz(observable, reps=2)
# the circuit is parametrized, so we will define the parameter values for execution
param_values = [0.1, 0.2, 0.3, 0.4]

print(f">>> Observable: {observable.paulis}")

Circuit i obserwowalna muszą zostać przekształcone tak, aby używały wyłącznie instrukcji obsługiwanych przez QPU (nazywanych zestawem architektury instrukcji (ISA) Circuitów). Użyjemy do tego Transpilera.

from qiskit.transpiler import generate_preset_pass_manager

pm = generate_preset_pass_manager(optimization_level=1, backend=backend)
isa_circuit = pm.run(circuit)
isa_observable = observable.apply_layout(isa_circuit.layout)
print(f">>> Circuit ops (ISA): {isa_circuit.count_ops()}")
>>> Circuit ops (ISA): OrderedDict([('rz', 3826), ('sx', 1601), ('cz', 968)])

3. Zainicjalizuj Qiskit Runtime Estimator​

Podczas inicjalizacji Estimatora użyj parametru mode, aby określić tryb, w którym ma działać. Możliwe wartości to obiekty batch, session lub backend — odpowiednio dla trybu wsadowego (batch), sesyjnego (session) i zadaniowego (job). Więcej informacji znajdziesz w artykule Wprowadzenie do trybów wykonania Qiskit Runtime.

from qiskit_ibm_runtime import EstimatorV2 as Estimator

estimator = Estimator(mode=backend)

4. Wywołaj Estimator i pobierz wyniki​

Następnie wywołaj metodę run(), aby obliczyć wartości oczekiwane dla podanych Circuitów i obserwowalnych. Circuit, obserwowalna oraz opcjonalne zestawy wartości parametrów są przekazywane jako krotki PUB (primitive unified bloc).

job = estimator.run([(isa_circuit, isa_observable, param_values)])
print(f">>> Job ID: {job.job_id()}")
print(f">>> Job Status: {job.status()}")

Zacznij pracę z Sampler​

1. Zainicjalizuj konto​

Ponieważ Qiskit Runtime Sampler jest usługą zarządzaną, najpierw musisz zainicjalizować swoje konto. Następnie możesz wybrać QPU, którego chcesz użyć do obliczenia wartości oczekiwanej.

Postępuj zgodnie z krokami opisanymi w temacie Instalacja i konfiguracja, jeśli nie masz jeszcze skonfigurowanego konta.

from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()
backend = service.least_busy(
    operational=True, simulator=False, min_num_qubits=127
)

2. Utwórz Circuit​

Do prymitywu Sampler potrzebny jest co najmniej jeden Circuit jako dane wejściowe.

import numpy as np
from qiskit.circuit.library import efficient_su2

circuit = efficient_su2(127, entanglement="linear")
circuit.measure_all()
# The circuit is parametrized, so we will define the parameter values for execution
param_values = np.random.rand(circuit.num_parameters)

Użyj Transpilera, aby uzyskać Circuit ISA.

from qiskit.transpiler import generate_preset_pass_manager

pm = generate_preset_pass_manager(optimization_level=1, backend=backend)
isa_circuit = pm.run(circuit)
print(f">>> Circuit ops (ISA): {isa_circuit.count_ops()}")
>>> Circuit ops (ISA): OrderedDict([('sx', 3089), ('rz', 3036), ('cz', 1092), ('measure', 127), ('barrier', 1)])

3. Zainicjalizuj Qiskit Runtime Sampler​

Podczas inicjalizacji Samplera użyj parametru mode, aby określić tryb, w którym ma działać. Możliwe wartości to obiekty batch, session lub backend — odpowiednio dla trybu wsadowego (batch), sesyjnego (session) i zadaniowego (job). Więcej informacji znajdziesz w artykule Wprowadzenie do trybów wykonania Qiskit Runtime. Pamiętaj, że użytkownicy planu Open Plan nie mogą przesyłać zadań sesyjnych.

from qiskit_ibm_runtime import SamplerV2 as Sampler

sampler = Sampler(mode=backend)

4. Wywołaj Sampler i pobierz wyniki​

Następnie wywołaj metodę run(), aby wygenerować dane wyjściowe. Circuit oraz opcjonalne zestawy wartości parametrów są przekazywane jako krotki PUB (primitive unified bloc).

job = sampler.run([(isa_circuit, param_values)])
print(f">>> Job ID: {job.job_id()}")
print(f">>> Job Status: {job.status()}")
>>> Job ID: d5k96rsjt3vs73ds5tig
>>> Job Status: QUEUED
result = job.result()

# Get results for the first (and only) PUB
pub_result = result[0]
print(

Zacznij pracę z prymitywami backend​

W przeciwieństwie do prymitywów specyficznych dla danego dostawcy, prymitywy backend to implementacje ogólne, które można używać z dowolnym obiektem backend, o ile implementuje on interfejs Backend.

  • Prymityw Sampler można uruchomić u dowolnego dostawcy, używając qiskit.primitives.BackendSamplerV2.
  • Prymityw Estimator można uruchomić u dowolnego dostawcy, używając qiskit.primitives.BackendEstimatorV2.

Niektórzy dostawcy implementują prymitywy natywnie. Szczegóły znajdziesz na stronie Qiskit Ecosystem.

Przykład: BackendEstimator​

from qiskit.primitives import BackendEstimatorV2
from <some_qiskit_provider> import QiskitProvider

provider = QiskitProvider()
backend = provider.get_backend('backend_name')
estimator = BackendEstimatorV2(backend)

Przykład: BackendSampler​

from qiskit.primitives import BackendSamplerV2
from <some_qiskit_provider> import QiskitProvider

provider = QiskitProvider()
backend = provider.get_backend('backend_name')
sampler = BackendSamplerV2(backend)

Podobieństwa i różnice między prymitywami backend a Runtime​

  • Dane wejściowe i wyjściowe dla qiskit.primitives.BackendSamplerV2 i qiskit.primitives.BackendEstimatorV2 są zgodne z tym samym formatem PUB co prymitywy w Qiskit Runtime. Szczegóły znajdziesz w artykule Dane wejściowe i wyjściowe prymitywów. Mogą jednak występować różnice w polach zwracanych metadanych.

  • Klasa qiskit.primitives.BackendEstimatorV2 nie oferuje gotowych implementacji mitygacji błędów pomiarowych ani bramkowych, ponieważ prymitywy backend są zaprojektowane do lokalnego uruchamiania na maszynie użytkownika.

  • Klasa qiskit.primitives.BackendSamplerV2 wymaga backendu obsługującego opcję memory.

  • Interfejsy prymitywów backend udostępniają własne opcje Options dla SamplerV2 i EstimatorV2, które różnią się od implementacji Runtime.
